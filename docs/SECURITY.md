# GoreeCloud VPN security boundaries

This source represents a **first-party control-plane preview**, not an operational VPN.

**Identity:** All peer registry APIs require one high-entropy bearer administrator token saved in an owner-only 0600 file. Only the /healthz and optionally enabled static UI assets are unauthenticated. There are no per-user roles, MFA, SSO or token rotation API. Use it on loopback, not the public Internet. Remote listeners require TLS and separate network/firewall access controls.

**Network:** Registering a peer produces a **pending, default-deny record**. Only a separately administrator-approved, non-revoked key is eligible for a new gateway snapshot; even approved registration is not an allowed WireGuard session or firewall permission. An additional private config exporter can emit conservative `AllowedIPs = 10.77.0.0/24` WireGuard client files with a locally held private key, written exclusively to new 0600 files; it never activates interfaces. Never conflate the registry's 10.77.0.0/24 development allocation with a production routed subnet. No routing, peer ACL, DNS, relay or kill switch is implemented. Do not automatically open gateways or assign public DNS based on this registry.

**Privacy:** The server stores device names, public keys and reserved addresses in a local owner-private directory; no analytics or telemetry are emitted. Browser and Android management credentials remain in memory. The Android tunnel configuration is imported via the OS file picker and remains process-memory only. OS VPN permission is requested only on user-initiated Connect; official GoBackend handles cryptography, not custom code. Sensitive data must be excluded from logs and public source. Android backups and cleartext traffic are disabled.

**Data safety:** The state path must be a real 0700 directory with a private state file. Atomic replace and fsync protect changes from partial writes, but an exclusive nonblocking Linux flock prevents a second daemon from operating on the same state directory. Store startup fails closed on malformed IDs, addresses, keys and approval/revocation chronology; run one daemon per state directory. Back up the private state outside public Git. No restore rehearsal has been completed.

**Threats remaining:** CSRF is not meaningful with explicitly supplied bearer headers and no credential cookies, but XSS, token theft from process memory, DoS/rate limits, certificate provisioning, log redaction, policy bypass, unsafe remote control, race conditions at runtime, peer revocation propagation, VPN DNS leaks and host firewall changes need independent review. A loopback-only preview must not be exposed through a publicly accessible reverse proxy without a production authentication and authorization design.

Security responsibilities: Wardveil handles cybersecurity and threat defense; GoreeShield governs consent/data minimization; GoreeCloud Identity must eventually enforce role-aware permissions. Mesh cannot expand authority by discovering an API.

**Native release gates:** The revised Android tunnel source must pass independent hosted compilation, and then actual consent-grant, consent-denial, live handshake, device-background and DNS/IPv6 negative tests. The Linux Qt source has a dedicated Qt 6.12 hosted compile gate and still requires hardware testing. The compiled React/Vite preview uses no browser token persistence; no public ingress is authorized until Identity, session and rate-limit controls are accepted.


**Network-namespace CI test guard:** The optional kernel WireGuard handshake test runs as root only in a disposable Linux GitHub Actions runner with an exact GoreeCloud repository check and cleans up its two private namespaces and temporary keys. It explicitly does not run on the laptop, live VPS, production NetBird or external hosts. Positive and negative packet checks are limited to generated synthetic 198.18.0.0/30 and 10.77.0.0/24 namespace addresses; the test must not be presented as live policy enforcement or recovery acceptance.


**Admission and revocation boundaries:** ApprovedAt is a durable administrator decision to include a key in an offline gateway snapshot, not a signed GoreeCloud Identity grant or live ACL. Unapproved peers and revoked peers are excluded and negative tests assert that. Revocation is not effective on a running gateway until the separately reviewed configuration is safely reconciled and actual packets are denied. The static admin bearer token must not be publicly exposed, and all peer actions ultimately require scoped Identity/RBAC.


**Service-level ACL preview:** The gateway-local nftables source generator now defaults to dropping INPUT and FORWARD traffic entering through the dedicated gateway WireGuard interface unless a narrowly reviewed key-bound service rule permits a gateway-local destination. The CLI never applies rules. The isolated GitHub CI namespace enforces a generated deny/allow test. Manual source input files can be forged by their own privileged operator, so this is not an end-to-end GoreeCloud Identity authorization assertion, dynamic policy convergence or full zero-trust network segmentation. Real deployments require signed policy source authority, least-privilege reconciliation, audit logs, drift detection, and independent recovery testing.
