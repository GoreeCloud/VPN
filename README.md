# GoreeCloud VPN

**Privacy-first, self-hosted Zero Trust networking platform.**

**Maturity: 0.1.0-alpha.2 — management-plane foundation only.** GoreeCloud VPN is designed for private WireGuard mesh connectivity, routing, network access control, private DNS, application publishing, remote access and observability. The full vision is recorded in [the capabilities specification](docs/FEATURES.md).

> **Not yet a functioning VPN.** This alpha does **not** create WireGuard tunnels, enforce packet-level access rules, deploy DNS, provide NAT traversal/relays, or install client VPNs. Do not use this code as a security boundary for production traffic.

## Working in the repository today

- Authenticated, loopback-only local management REST API
- SQLite peer inventory with unique private IPv4 allocation
- Device identity lifecycle: pending → key possession proven → administrator approved → revoked; proof must be fresh before approval
- Only approved peers participate in management policy decisions or private DNS previews
- Local peer lifecycle event history; events are not tamper-proof audit evidence
- Read-only approved-peer planning and inspectable, unapplied WireGuard peer stanzas
- Public WireGuard key format validation; private keys remain on devices
- Group-scoped, directional TCP/UDP/ICMP allow policies with a default-deny *decision evaluator*
- Administrative peer and policy lifecycle APIs
- Preview of internal DNS A records (not a live DNS server)
- Input validation, request size limits, owner-restricted database and constant-time bearer-token comparison
- Management status with lifecycle/group counts and address-pool capacity
- Explainable access decisions and bounded batch simulation against current policies
- Static policy diagnostics for duplicate rules and rules without eligible approved peers
- Filtered, cursor-paginated local lifecycle history
- Local inspection CLI (`goreecloud-vpnctl`) with JSON output
- Automated tests and CI configuration

## Install and start (local development)

Requirements: Python 3.11+.

    python -m pip install -e .
    export GOREECLOUD_VPN_ADMIN_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
    goreecloud-vpn --host 127.0.0.1 --port 8176

No administrator token is embedded in the source or generated by the server. The API refuses to bind to non-loopback interfaces. Each request must use the exact bound loopback IP literal and port in a single `Host` header (for example `127.0.0.1:8176` or `[::1]:8176`); browser-originated requests are rejected until a separate, reviewed browser authentication design exists. IPv6-only local management is also supported using `--host ::1`; it binds an IPv6 loopback socket and never a wildcard listener. Keep the runtime token private and do not publish the SQLite database. The default private address range (10.234.12.0/24) is illustrative; check subnet collisions before actual network design.

To check status or list peers:

    curl http://127.0.0.1:8176/healthz
    curl -H "Authorization: Bearer $GOREECLOUD_VPN_ADMIN_TOKEN" http://127.0.0.1:8176/api/v1/peers

To register a peer, supply a **public** WireGuard key generated on that peer:

    curl -X POST http://127.0.0.1:8176/api/v1/peers \
      -H "Authorization: Bearer $GOREECLOUD_VPN_ADMIN_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"name":"laptop","public_key":"REPLACE_WITH_REAL_PUBLIC_KEY","groups":["users"]}'

New peer records remain `pending` until an administrator verifies a short-lived proof of possession of the device-held WireGuard private key and approves within five minutes. Previously approved records are reset to pending when upgrading from the pre-proof schema. The private key must never be transmitted to the management server. See [the local key-possession protocol](docs/KEY_PROOF.md). After the proof has been verified, the administrator can approve:

    curl -X POST -H "Authorization: Bearer $GOREECLOUD_VPN_ADMIN_TOKEN" http://127.0.0.1:8176/api/v1/peers/PEER_ID/approve

To revoke a peer, use `POST /api/v1/peers/PEER_ID/revoke` or `DELETE /api/v1/peers/PEER_ID`. Revocation is terminal: the record and public-key tombstone remain in the database so the same key cannot be enrolled again. To replace a revoked peer, use a **new** public key and device name. Changes made here still do **not** control real WireGuard packets.

To create a directional management policy allowing TCP/22 from group `users` to `servers`:

    curl -X POST http://127.0.0.1:8176/api/v1/policies \
      -H "Authorization: Bearer $GOREECLOUD_VPN_ADMIN_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{"source":"users","target":"servers","protocol":"tcp","ports":[22]}'

**Important:** These rules are currently stored and evaluated by the management service only. Until actual VPN agents and firewall policy enforcement are implemented and tested, the returned allowed/denied decision does **not** restrict real network traffic.

## API contract

| Method | Endpoint | Behavior |
|---|---|---|
| GET | /healthz | Minimal unauthenticated process health |
| GET, POST | /api/v1/peers | List and register peer metadata |
| POST | /api/v1/peers/{id}/challenge | Issue a single-use short-lived key-possession challenge |
| POST | /api/v1/peers/{id}/prove | Verify the device-produced proof against the registered public key |
| POST | /api/v1/peers/{id}/approve | Approve a pending peer with fresh verified proof (admin only) |
| POST | /api/v1/peers/{id}/revoke | Irreversibly revoke a peer record (admin only) |
| DELETE | /api/v1/peers/{id} | Revoke peer while retaining a key tombstone |
| GET | /api/v1/events | Filtered lifecycle history with cursor pagination (default 200); not tamper-proof |
| GET | /api/v1/peers/{id}/plan | Admin-only connectivity intent preview; no actual enforcement |
| GET, POST | /api/v1/policies | List and create allow policies |
| DELETE | /api/v1/policies/{id} | Delete policy |
| POST | /api/v1/access/check | Management-only directional policy decision |
| GET | /api/v1/dns | Preview A records; DNS server not active |
| GET | /api/v1/status | Management counts, group inventory and address-pool usage (not live VPN health) |
| GET | /api/v1/policies/diagnostics | Eligible peer-pair counts, inactive-rule warnings and exact duplicate sets |
| POST | /api/v1/access/explain | Decision reason and matching policy IDs; no enforcement |
| POST | /api/v1/access/simulate | Evaluate 1–100 access queries against current management state |

All endpoints except /healthz require `Authorization: Bearer <admin-token>`. Request bodies are JSON with a 16 KiB limit.

Inspect management state from a second terminal using the same administrator token:

    goreecloud-vpnctl status
    goreecloud-vpnctl diagnostics
    goreecloud-vpnctl events --limit 20

See [management inspection](docs/MANAGEMENT_INSPECTION.md) for CLI usage, batch
simulation, decision reasons, pagination and limitations. These are local
administrative tools, **not a functioning VPN client or live health monitor**.

Run the test suite:

    python -m unittest discover -s tests -v

For a nonpublishing wheel/package-integrity check:

    python -m pip wheel --no-deps --wheel-dir dist .
    python scripts/verify_wheel.py dist

This confirms build metadata, inclusion of the MIT license, and a basic wheel file manifest; it does not establish a deployable VPN or a signed production release.

## Ecosystem boundaries

[GoreeCloud Mesh](https://github.com/GoreeCloud/mesh) is the ecosystem integration/orchestration fabric, not a duplicate VPN data plane. [GoreeCloud UI](https://github.com/GoreeCloud/gc-ui) is the authoritative design system for future user-facing VPN applications.

No NetBird/Tailscale service, production host, keys, subnet, or deployment is modified by this repository. No third-party implementation is represented as owned GoreeCloud code.
